# MS2 slide content checklist

This is an outline for collecting team contributions, not a completed deck. Akshaya assembles the supplied material; component owners supply and verify the claims and artifacts for their sections.

1. **Problem and MS2 scope - Ming.** Identify the user and show the profile-to-course-retrieval slice. State which proposal features are deferred.
2. **Acceptance examples - Ming.** Include five representative queries, expected courses or evidence, and how relevance will be judged.
3. **Data and provenance - John.** Show actual record count, snapshot ID, source URLs/dates, cleaning/deduplication, and unresolved fields. Use only measured counts from the selected snapshot.
4. **Retrieval - Shravya.** Show chunking, embedding model/version, vector database, and one actual query-to-context input/output. Record failures as well as successes.
5. **Containers and reproducibility - Tavish.** Show service boundaries, uv/dependencies, the full one-command workflow, running-instance screenshot, and clean-checkout evidence.
6. **Frontend demo - Akshaya.** Show the profile form, actual returned course cards, supporting context/source links, version metadata, and loading/empty/error behavior. Label synthetic screenshots while integration is pending.
7. **Results and gaps - Team.** Summarize the five acceptance outcomes, which evidence is complete, current failures, and scope limits. Distinguish implemented code from executed integration.
8. **Next steps and submission - Team.** Identify the next technical iteration and the exact verified milestone2 commit. Do not claim Canvas submission until a team member confirms it.

Attach each source artifact to the [evidence register](evidence.md). Rehearse using the [demo runbook](demo-runbook.md), keeping the presentation to 15 minutes plus TF Q&A.
